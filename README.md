# Мой бюджет

Бесплатное мобильное веб-приложение для нерегулярного дохода: ожидаемые выплаты после смен, кредиты, конверты, бензин и ремонт, подушка с растущими рубежами и переезд (300 000 ₽).

## Локальный запуск

Нужны Python 3 и Node.js 18+ для тестов. Внешние пакеты и установка зависимостей не нужны.

```sh
cd /workspace/guess_number
npm test
npm run check
npm start
```

Порт 5173. Интерфейс без настройки работает локально; это **не аккаунт и не облачная резервная копия**. Данные сохраняются в браузере. Ранее сохранённые остатки не меняются при обновлении. Каждый доход распределяется по настраиваемым процентам шести категорий, включая кредиты. Сумма долей должна быть 100%; поддерживаются сотые доли процента. Округление сохраняет все копейки. Доля кредитов резервируется по датам платежей. Любые категории поддерживают переводы. Удаление платежа сохраняет деньги в конверте кредитов. Добавляйте ближайший платёж, а не все будущие платежи кредита. Автосписаний и банковских подключений нет. Общий баланс включает целевые накопления, он не является суммой для свободных трат.

## Аккаунты и бесплатное размещение

1. Создайте проект **Supabase Free**, без банковской карты и платных дополнений. Условия бесплатных тарифов необходимо проверить непосредственно при регистрации: в этой среде актуальные квоты не проверены. При требовании оплаты остановитесь.
2. Выполните `supabase/schema.sql` в SQL Editor один раз. RLS изолирует данные пользователей. Для проверки создайте два тестовых аккаунта: второй не должен читать или менять строку первого (проверять также прямым REST-запросом).
3. В `config.js` укажите HTTPS Project URL и публичный **anon key** из Supabase. Это публичные параметры, не service_role и не пароль. Никогда не используйте service_role в браузере.
4. В Authentication включите Email/Password и подтверждение почты. Задайте Site URL и допустимые Redirect URLs вашего опубликованного адреса. Для локального тестирования добавьте соответствующий локальный адрес. Возможности отправки почты бесплатного проекта ограничены: проверьте регистрацию, подтверждение и восстановление на своём адресе. Если стандартный отправитель не доставляет письма пользователям, понадобится бесплатный SMTP-провайдер; не отключайте подтверждение лишь для обхода проблемы. До проверки доставки восстановление доступа не считается готовым.
5. Разместите статические файлы на **Cloudflare Pages Free**, без сборки. Публикуйте только `index.html`, `style.css`, `app.js`, `budget.js`, `config.js`, `icon.svg`, `manifest.webmanifest`. Git-интеграция необязательна: можно загрузить папку с этими файлами вручную. Бесплатный адрес `*.pages.dev`; домен покупать не требуется. Требуется HTTPS. Платные функции не включайте.
6. Проверьте на телефоне: регистрацию, письмо, вход, создание платежа, доход, трату, выход, повторный вход, восстановление пароля. На другом устройстве должен появиться тот же бюджет. Затем проверьте экспорт и восстановление JSON. Можно добавить сайт на главный экран через меню браузера.

Аккаунты не переносят локальные записи автоматически. Для переноса скачайте копию до входа и восстановите после входа. Аккаунт хранится в sessionStorage, после закрытия вкладки может потребоваться повторный вход. При сбое облака изменения блокируются, чтобы не затереть серверные данные; восстановите связь в настройках. Одновременное редактирование на нескольких устройствах не поддерживается: перед изменениями откройте приложение заново или нажмите «Восстановить связь». Последняя запись заменяет бюджет целиком.

## Резервные копии и ограничения

Регулярно экспортируйте JSON. Он содержит личные финансовые данные без шифрования; не публикуйте его. Бесплатные сервисы могут менять лимиты, приостанавливать неактивные проекты и ограничивать письма. Собственный сервер не нужен, но аккаунты требуют внешнего сервиса. Локальный режим доступен без него. Приложение не обещает постоянную доступность бесплатных сервисов и не подключает оплату автоматически.

Удаление данных браузера удаляет локальный бюджет. Выход из аккаунта не удаляет облачные данные. Подушка показывает следующий общий накопительный рубеж; после расходования показывает актуальный рубеж снова. Кредитные платежи вводятся вручную, повторяющиеся платежи пока не создаются автоматически.

Название проекта в приложении — «Мой бюджет», техническое имя — `my-budget`. Переименование репозитория GitHub выполняется отдельно в Settings → General → Repository name; локальная папка оставлена на прежнем месте для совместимости с облачной средой.

## Установка на телефон

Откройте сайт по HTTPS. Android/Chrome: меню → «Установить приложение»; iPhone/Safari: «Поделиться» → «На экран Домой». В настройках приложения также есть кнопка установки. Это устанавливаемое веб-приложение (PWA), без магазинов и оплаты. После первого открытия локальные операции доступны без сети. Перед проверкой офлайн дождитесь загрузки страницы и перезапустите её. Аккаунт и синхронизация требуют сети. При размещении включите в публикацию sw.js и обе PNG-иконки. Обновления загружаются при открытии с интернетом; после обновления закройте и снова откройте приложение.

## Импорт выписки Сбера

Вкладка «Банк» → «PDF Сбера» → выбрать полную текстовую выписку → проверить итоги → «Импортировать». Поддержан формат «Выписка по платёжному счёту», проверенный на 12-страничном документе. Фото, сканы, защищённые PDF и другие форматы не поддерживаются. Лимит: 20 МБ и 150 страниц. При несовпадении сумм импорт останавливается.

Направление операций определяется по изменению остатка между соседними строками. Суммы всех операций сверяются с итоговыми пополнениями/списаниями и начальным/конечным остатком. Показывается баланс на дату выписки, а не в реальном времени. Один банковский счёт; номер счёта используется лишь для локального SHA-256 отпечатка и не сохраняется в данных. ФИО из шапки документа не импортируется. Описания операций могут содержать личные сведения.

В текущем локальном режиме PDF обрабатывается на устройстве без внешних запросов; сам файл не сохраняется. Результат хранится в браузере и входит в JSON-резервную копию. Если позже подключить аккаунт Supabase, результат вместе с бюджетом будет синхронизироваться с ним. «Удалить банковские данные» удаляет импортированные операции, не изменяя конверты.

Повторный PDF определяется по SHA-256; перекрывающиеся операции сравниваются по дате, времени, сумме, остатку и описанию. При изменении банком текста описания возможны дубли. Разные операции с одинаковыми полями сохраняются с учётом количества повторов. Категории приблизительные; переводы между своими счетами не следует считать заработком. Импорт не меняет конверты и не создаёт доход автоматически.

PDF.js 6.4.299 включён в vendor/pdfjs, лицензия Apache-2.0 рядом. Источник: npm pdfjs-dist@6.4.299. SHA-512 архива проверен: sha512-AVl138zALtfaAPvADulE0PZThbYzCBS79nL4pOSL/6Sm/4AH5A21BD9VHt97OlCuzJuCpmeZtAtkinisF4Vb1g==. В публикацию включайте bank.js, pdf-import.js и vendor/pdfjs. Тестовые данные в tests/bank.test.js синтетические; исходная пользовательская выписка в репозиторий не включается.

## Ежедневное планирование и исправления

Главный экран отдельно показывает повседневный конверт и общий баланс. Предупреждения по платежам ближайших 14 дней учитывают неоплаченные обязательства и только вручную записанные ожидаемые выплаты с датой не позже срока платежа. Прогноз не гарантирует поступление. Ориентир процента кредитов рассчитан по сумме ожидаемых выплат; изменение долей остаётся ручным.

Новые финансовые операции сохраняют распределение по категориям. В истории доступны редактирование суммы, даты, категории/направления и описания, а также отмена. Перед подтверждением показаны будущие остатки. Если обратная операция создаёт отрицательный остаток, исправление/отмена блокируется. Доход корректируется с процентами на момент его создания. Кредитный платёж можно отменить и оплатить заново; если соответствующий платёж удалён, отмена недоступна. Старые записи не имеют достаточных данных для восстановления распределения и остаются без исправлений.

На расход/перевод из подушки или переезда нужно отдельное подтверждение. Блок дохода за вычетом затрат на машину учитывает только новые структурированные записи, все доходы условно считает рабочими и показывает фактические расходы на бензин/ремонт. Отложенный резерв показан отдельно, он не вычитается как фактический расход. Сравнение отдельных смен пока не реализовано.

В банковской истории «Разобрать» предлагает: подтвердить новый доход, новый расход с категорией, связать с уже записанной операцией или пропустить перевод/прочее. Подсказка совпадения требует одинаковой суммы и даты в пределах трёх дней, но не доказывает, что это одна операция. Решение принимает пользователь. Кредиты оплачиваются в своём разделе, затем банковский платёж связывается с записью оплаты. Автоматического списания по факту импорта нет. Подтверждённая новая операция меняет конверты и становится доступна для отмены в истории. Отмена снимает привязку к банку. Для пропущенных/связанных операций есть «Пересмотреть». Всё работает локально и без новых сервисов.

## Оформление

В настройках выбираются светлая, тёмная или системная тема и акцент (лаванда, мята, персик). Системная тема реагирует на изменения настроек устройства. Выбор сохраняется локально отдельно от бюджета. Для публикации нужен appearance.js; он применяется до загрузки стилей.

Главный экран показывает свободные деньги, одну приоритетную подсказку (кредит, выплата, разбор выписки), компактные конверты и цель переезда. Подробный план кредитов, ожидаемые выплаты и учёт затрат свёрнуты.

«Скрыть суммы» заменяет отображаемые денежные суммы точками и сохраняет выбор. Это визуальный режим, а не шифрование: значения в формах редактирования, файлах копий и хранилище браузера остаются доступны.

## Вариант оформления 01 — банковский

Первый вариант для сравнения: нейтральные белые/графитовые поверхности, тонкие разделители, компактная типографика и минимальные скругления. Цвета акцента: синий, зелёный, бронза. Выбор светлой/тёмной/системной темы и скрытие сумм сохраняются. Это визуальное обновление, данные бюджета не мигрируют и не перераспределяются. Предыдущий вариант сохранён в истории Git.
